DNS Security Simulation

Python • TCP/IP • RSA-PSS • SHA-256 • Cryptography

A Python client/server application that demonstrates why digital signatures are essential to DNS integrity. It shows how a client can refuse an altered DNS answer instead of trusting data solely because it came from a server.

Overview

The program implements a small DNS-like protocol over a TCP socket. The server stores two example A records, signs a structured response with an RSA private key, and returns the public key and a cryptographic signature. The client validates the response using a public-key file stored locally as its trust anchor.

Request and Response Flow

Client                                     Server
  |                                         |
  |-- DNS query, transaction ID, nonce ---->|
  |                                         |-- Look up A record
  |                                         |-- Build canonical record
  |                                         |-- Sign with RSA-PSS/SHA-256
  |<------- Signed DNS-style response -------|
  |
  |-- Verify key, identity, freshness,
  |   transaction, nonce, and signature

Security Checks

  • Key trust: the client loads server_public.pem and compares both the response key and key fingerprint against it.
  • Replay protection: transaction IDs and random nonces bind the response to the original query.
  • Freshness: each response contains inception and expiration timestamps with a 60-second lifetime.
  • Canonical signing: name, record type, address, TTL, key ID, timestamps, transaction ID, and nonce are serialized in a deterministic format before signing.
  • Signature verification: RSA-PSS with SHA-256 detects any change to the signed record fields.
  • Input validation: record types, IP addresses, response types, and status values are checked before an address is accepted.

Tampering Demonstrations

The client includes commented test mutations for the response address, transaction ID, nonce, expiration, key ID, and signature. Each mutation can be enabled individually to demonstrate rejection. The result is a local security failure rather than a silently accepted modified address.

Implementation Details

The server generates a 2048-bit RSA key pair on first run and stores the private key in an encrypted PKCS8 PEM file protected by a user-entered password. Later runs load the existing key pair so signatures remain tied to the same trust anchor.

The project also verifies a known-good signature and deliberately alters a signed record in main(), proving that the public key rejects the tampered record with InvalidSignature.

Scope and Limitations

This is an educational simulation, not a replacement for DNS or a complete DNSSEC implementation. It does not implement DNS zone hierarchies, DNSSEC chains of trust, DS records, DNSSEC signing keys, UDP queries, caching, or real-world resolver infrastructure. Its purpose is to make the core property of signed DNS data clear: a resolver should validate authenticity and integrity before accepting an answer.

Running the Demo

python -m pip install -r requirements.txt
python secure_message.py

In a second terminal:

python -c "import secure_message; secure_message.run_client('127.0.0.1', 5300, 'www.example.com', 'A')"
